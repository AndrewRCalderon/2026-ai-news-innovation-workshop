# Revisit & Build

> You've spent the day learning how to prompt, configure, and plan more deliberately. Now bring that back to the project you started yesterday.

## 1. State Your Goal, Then Plan

This isn't starting over. It's the same project, with a full day of better tools than you had this morning. This is where they all come together.

Before you touch any code, check whether the pieces from today still hold up:

- Does your CLAUDE.md still describe what you're actually building, or does it need an update first?
- If you ran your project through this afternoon's spec checklist right now, what's missing?

Then open plan mode. State what you want to do next in plain language, the way you'd explain it to a colleague, and let Claude research and propose an approach. Read the plan before you approve it. Is it specific to your actual project, or generic enough to apply to anything? Send it back and ask Claude to keep planning if it's not right yet, that's the point of plan mode, not a sign something went wrong.

Along the way, notice if you're explaining the same thing to Claude more than once, today or in a project you'll come back to. That's usually a sign it's worth turning into a Skill instead of just fixing it in the moment. Ask Claude about it directly, or note it and come back to it once you're building.

## 2. Build

Most of this session is just time to work. The instructor will circulate one-on-one rather than teaching from the front, so use that time.

> **Exercise: Build Time**
> - Time: The rest of this session.
> - Description: Build from the plan you just reviewed. Update your CLAUDE.md if it needs it, write or revise a spec for what you're building next, then build.
> - Deliverable: Visible progress on your project, not a finished product. Something to show and talk about next.

### If you're not sure where to start

- Pick one small piece rather than redoing everything from scratch.
- Apply the spec checklist to just your next feature, not the whole project.
- Ask Claude directly: "given everything we've covered today, how would you approach this differently than yesterday?"
