Skills & Best Practices

Two ways to get more consistent results from Claude: package your expertise so it doesn't need re-explaining, and follow a few habits Anthropic's own engineers recommend.

01

What a Skill Is

A Skill is a reusable, filesystem-based resource: a folder of instructions, scripts, and reference material that gives Claude domain-specific expertise, organized roughly like an onboarding guide you'd hand a new hire.*

The difference from just writing a good prompt: a prompt is conversation-level, for one task. A Skill loads on demand, so the same guidance doesn't need repeating across every new conversation.* Anthropic introduced Skills in October 2025, framing them around a simple idea: real work needs procedural knowledge and organizational context, not just a capable model.*

02

What Actually Makes This Work

Anthropic publishes its own best-practices guide for Claude Code, and most of it comes down to giving Claude something concrete to check itself against.*

  • Give Claude a way to verify its own work: tests, a build, a screenshot to compare. It's the difference between a session you have to watch and one you can walk away from.*
  • If you've corrected the same issue twice in one session, the context is cluttered with failed approaches. Clear it and start over with a more specific prompt.*
  • Delegate research separately from implementation, so exploring a codebase doesn't clutter the conversation you're actually building in.*
03

Vague vs. Specific

Claude can infer intent, but it can't read your mind.* The same request, made specific, gets a very different result:

Vague

  • "add tests for foo.py"
  • "implement a function that validates email addresses"

Specific

  • "write a test for foo.py covering the edge case where the user is logged out. avoid mocks."
  • "write a validateEmail function. example test cases: user@example.com is true, invalid is false. run the tests after implementing."
04

Common Failure Patterns

Anthropic's own guide names a handful of recurring failure modes. Two worth watching for in your own sessions today:

The kitchen sink session
Piling unrelated tasks into one long conversation until Claude loses the thread. Fix: one goal per session.
The trust-then-verify gap
Assuming code that runs is code that's correct. Fix: the verification step from above isn't optional.

A Skill is stored expertise. The point, same as CLAUDE.md, is not re-explaining what you already know.
