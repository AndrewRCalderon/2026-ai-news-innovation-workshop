01

What a Skill Is

A Skill is a reusable, filesystem-based resource: a folder of instructions, scripts, and reference material that gives Claude domain-specific expertise, organized roughly like an onboarding guide you'd hand a new hire.*

The difference from just writing a good prompt: a prompt is conversation-level, for one task. A Skill loads on demand, so the same guidance doesn't need repeating across every new conversation.* Anthropic introduced Skills in October 2025, framing them around a simple idea: real work needs procedural knowledge and organizational context, not just a capable model.*

People have already built skills for this exact job: a 14-skill collection for journalists covers AP style, source and deepfake verification, and FOIA request templates, free to install.* Worth a look after this session.

02

What Actually Makes This Work

The team that built Claude Code uses Skills internally for its own production work, and their account of what makes one hold up is sharper than the general best-practices advice.*

  • The highest-signal content in any skill is its Gotchas section, and it should be built from failures you actually watched happen, not ones you imagined in advance.*
  • Run the task once without the skill loaded before you trust it. Without that baseline, you can't actually tell what the skill changed, only that something ran.*
  • A skill fails to activate before it fails to execute. A vague description like "helps with content creation" won't reliably trigger, a specific one describing exactly when to use it will.*
03

A Real Investigation

A journalism researcher used Claude Code to replicate a real MuckRock/WHRO investigation into Virginia police decertifications, in under an hour.* Without a data skill enforcing provenance and a documented methodology, Claude silently reformatted non-standard dates and undercounted the result. With one, it matched the published investigation exactly:

Without the skill

  • Silently handled date-formatting anomalies
  • Reported 80 decertifications, undercounted

With the skill

  • Required provenance columns and a data-quality report before any transform
  • Reported 81, matching the published investigation

Even with skills enforcing the process, a human still had to catch what the model couldn't: Unicode apostrophe variants in agency names, and whether "Hampton Police Department" and "Hampton Police Division" were the same entity.* "Configuration matters as much as capability," Hagar writes. "A powerful model without the right constraints will move fast and make mistakes."*

04

Common Failure Patterns

Independent builders who've shipped dozens of skills describe the same failures in their own words, worth watching for in your own sessions today:

The confident-looking failure
A skill that passes the test cases you wrote for it can still fail on real input, reordering sections, dropping fields, inventing ones that were never there. Fix: test it against messy, real input, not just the cases it was built to pass.*
The patch spiral
Treating every new failure as a one-line edit until the skill accumulates contradictory rules nobody remembers the reason for. Fix: after a couple of patches, rebuild from what actually failed instead of layering on another exception.*
Installing skills from strangers
One public skills marketplace passed 40,000 listings within months of launch, and shared skill repos have already been found shipping malware that exfiltrates tokens and cloud credentials. Fix: read a skill's actual instructions before installing it, the same way you'd check a browser extension's permissions.*

A Skill is stored expertise. The point, same as CLAUDE.md, is not re-explaining what you already know, but a skill you've never tested without is a skill you don't actually understand.
