Your Goal & Plan Mode

Before Claude touches any code, it can research and propose an approach first. Knowing when that's worth it is the actual skill.

12:20 PM·40 MIN·Hands-on
01

What Plan Mode Is

Plan mode tells Claude to research and propose changes without making them. Edits stay blocked until you approve the plan.

Turn it on with Shift+Tab, or start a prompt with /plan. Once the plan's ready, approve it, approve but review each change, or send it back to keep planning.

In VS Code, the plan opens as a real Markdown document, so you can highlight a piece of it and comment directly.

02

When to Use It

Jumping straight to coding can produce code that solves the wrong problem, wastes tokens, and jumbles up your codebase.

A bad plan is a paragraph. A bad implementation is an afternoon.

Three criteria that can help you intuit whether you should use plan mode:

  • Uncertainty. Do you know the approach, or are you still figuring out "done"?
  • Blast radius. One easy-to-undo file, or several touching something hard to reverse?
  • Familiarity. Code you know well, or a part you haven't touched?

Fast check: if you could describe the change in one sentence, skip the plan.

03

The Other Failure Mode

Over-relying on planning becomes its own tax. One account: giant multi-page plans, hard to review, and feedback triggered a full regeneration instead of a targeted edit.

Rubber-stamping
A long plan gets skimmed and approved, not actually read.
Plan drift
Long sessions can quietly drop details the plan depended on.

Keep it short enough to read. Act on it soon after you approve it.
