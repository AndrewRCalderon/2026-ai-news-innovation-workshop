Spec-Driven Development

AI models are excellent at pattern completion and poor at mind reading. A spec closes that gap.

2:00 PM·30 MIN·Lecture
01

The Core Idea

Spec-driven development inverts the usual workflow: the spec becomes the source of truth, code becomes a generated or verified secondary artifact.

The spec declares intent, the code realizes it. A vague prompt leaves Claude guessing. A spec gives it enough to match your intent instead of inventing one.

02

The Checklist

  1. 1

    Specify

    What should it do? No implementation details yet.

  2. 2

    Plan

    How should you build it? The plan declares constraints.

  3. 3

    Implement

    Small, validated increments.

  4. 4

    Validate

    Does the code meet the spec? The spec stays the authority.

03

Why This Connects to Skills

Specs, done well, act as modular building blocks Claude can work from directly, close to what a Skill does when it packages expertise for reuse.

A Skill is essentially a pre-written spec for a kind of task you'll do again.
