01

What It Is

CLAUDE.md is a plain-text file Claude reads automatically at the start of every session. Without it, you're re-explaining your project from scratch, every time.

A simple test for whether something belongs in yours: has Claude made the same mistake twice, or have you typed the same correction more than once? That's the signal. If it's only sometimes relevant, that's a Skill instead, next session.

02

A Real Example

This workshop's own repo has a CLAUDE.md file. It's not hypothetical, it's the actual file governing this website's build.

It points, it doesn't duplicate
Delegates to other files instead of repeating them.
States what can't be inferred
Rules Claude couldn't guess from reading code, like a robotics lab's note that existing code is human-verified but not necessarily optimal.
Organized by when you'd need it
Maps to actual moments in a session.
03

What Belongs In One

The most common mistake isn't leaving something out. It's putting too much in.

Not just this repo's habit: Cloudflare, the 52k-star Block/goose, and Next.js all use CLAUDE.md as a one-line pointer to AGENTS.md, via Claude Code's own @path/to/import syntax.

Include

  • Commands Claude can't guess
  • Non-default code style rules
  • Testing instructions
  • Repo etiquette
  • Project-specific architecture decisions
  • Non-obvious gotchas

Leave out

  • Anything inferable from code
  • Tutorials on tools Claude already knows
  • File-by-file codebase descriptions
  • Self-evident practices ("write clean code")
  • Credentials, ever

A real 51-line security-scanner CLAUDE.md vs. a real 868-line one, a sixth of it a tutorial Claude didn't need. Same goal, radically different discipline.
