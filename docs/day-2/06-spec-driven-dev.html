01

The Core Idea

Spec-driven development inverts the usual workflow: the specification becomes the source of truth, and code becomes a generated or verified secondary artifact.* Put another way: the spec declares intent, the code realizes it.*

Why this matters more with AI assistants than it used to: AI models are excellent at pattern completion, and poor at mind reading.* A vague prompt like "add photo sharing to my app" leaves Claude guessing at what you actually meant. A spec gives it enough to match your intent instead of inventing one.

02

The Checklist

A repeatable four-step framework, worth applying to your own project this afternoon.*

  1. 1

    Specify

    What should it do? Behavior, requirements, acceptance criteria, no implementation details yet.

  2. 2

    Plan

    How should you build it? Architecture, data models, interfaces. The spec declares intent; the plan declares constraints.

  3. 3

    Implement

    Small, validated increments, each one a testable piece of functionality, not one giant leap.

  4. 4

    Validate

    Does the code actually meet the spec? If not: was the spec wrong, or the code? Either way, the spec stays the authority.

What makes step 1 actually work: a good spec is behavior-focused (what happens, not how), testable, unambiguous, and complete enough without over-specifying.* One practical rule of thumb: if there's only one reasonable way to read a requirement, don't add more detail. If there's more than one, that's exactly where to add clarification.*

A passing test only proves the code matches the spec, not that the spec was right in the first place. If the spec was wrong, the code will faithfully implement the wrong thing.*

03

Why This Connects to Skills

Specs, done well, act as modular building blocks Claude can work from directly, close to what a Skill is doing when it packages expertise for reuse.* A Skill is essentially a pre-written spec for a kind of task you'll do again. Once you've written a spec once, the checklist above is what makes it repeatable the next time.
