Why This Session

AI Tools gave you the landscape. This session is different: it's hands-on and instructor-guided, working through the three tools you'll actually use for the rest of the workshop — VS Code, Claude Code, and GitHub — so nothing is unfamiliar when it's time to build.

04

Claude Code: Best Practices & Mindset

There isn't a fixed set of steps to memorize here — the real way to get good at Claude Code is to use it. What follows are guardrails, not a checklist: a few habits that make the difference between fighting the tool and working well with it. Once you've got these, the rest of today is practice.

  • Be specific. Vague asks get vague results. "Add filtering" is weaker than "add a dropdown that filters the article list by topic."
  • Use Plan Mode for anything non-trivial. Review what it's about to do before it does it — that's the moment to catch a misunderstanding cheaply.
  • Give it context. Point it at relevant files or explain the project rather than assuming it can guess what you mean.
  • Work in small steps. A series of small, specific asks beats one giant one — easier to review, easier to course-correct.
  • Always read the diff. You're still responsible for what ships, not Claude Code. Reviewing is part of the job, not optional.
  • Clarify, don't fight. If the result is off, restate what you actually want rather than repeating the same prompt harder.
  • Treat surprises as information. It won't be right every time — that's normal, not a sign you're doing something wrong.
The fastest way to get good at this is to use it. Treat today's project time as low-stakes practice.
05

GitHub Walkthrough

The general mechanics of Git/GitHub inside VS Code — the actual workshop fork-and-submit workflow gets its own session right after this one:

  • Open the Source Control panel (the branching icon in the left sidebar).
  • See which files have changed since your last commit.
  • Stage a change, write a commit message, and commit.
  • Push — sends your commits to GitHub.

Next up: forking the actual workshop repo and setting up the branch/commit/PR workflow you'll use to submit your work.

06

How They Work Together

VS Code is your editor. Claude Code is your AI pair programmer. GitHub is your project home. Here's what a real session looks like — say you want to build a tool that analyzes news articles:

  1. 1

    Ideation

    Describe the problem to Claude Code in plain language.

  2. 2

    Planning

    Claude Code shows you a plan before touching anything.

  3. 3

    Building

    It writes the code; you see it in VS Code, edit, ask questions, iterate.

  4. 4

    Testing

    Claude Code can run your app locally so you can try it.

  5. 5

    Shipping

    Commit to GitHub, open a PR. Done.
