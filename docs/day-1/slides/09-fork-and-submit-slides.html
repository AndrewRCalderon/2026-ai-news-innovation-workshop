Fork & Submit

One-time setup that connects your work to the shared repo — do this now, and submitting is just a commit and a PR from here on.

3:50 PM·40 MIN·Hands-on
01

Why This Matters

Everything you build today gets submitted the same way: as a Pull Request against the shared workshop repo. This session is the one-time setup that makes that possible.

02

What Is a Fork?

Your own personal copy of the shared repo, under your own GitHub account. Change anything, freely — then open a Pull Request to propose merging it back. The instructor reviews and merges.

Everyone forks the same repo, works in their own folder, submits the same way.

03

Fork the Workshop Repo

  • Go to github.com/AndrewRCalderon/2026-ai-news-innovation-workshop.
  • Click Fork, top-right.
  • Confirm — it lands under your own account.
04

Clone Your Fork Into VS Code

  • GitHub Desktop: File → Clone Repository, pick your fork.
  • Direct Git: copy your fork's URL, git clone <URL>.
  • Open the cloned folder in VS Code.
05

Create Your Branch & Work in Your Folder

  • Create a day-1 branch — or ask Claude Code to do it.
  • Work inside submissions/day-1/your-name/.
06

Commit, Push, Open a PR

  • Commit with a real message — Claude Code can do this for you.
  • Push your day-1 branch to your fork.
  • Open a Pull Request into the shared repo's main. That's your submission.
07

What Happens Next

The instructor merges everyone's PRs at day's end. Tomorrow's Day 2 branch starts from the updated main — already including your merged Day 1 work.

Fork once, today. From here, it's just a commit and a PR.
